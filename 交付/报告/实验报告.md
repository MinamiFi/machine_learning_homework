## 摘要

本项目按题目要求实现了一个**具备记忆模块的对话智能体**：用浅层全连接神经网络对历史记忆片段的向量表征打分，依据分数在固定 token 预算下筛选记忆，从而在控制上下文开销的同时保留关键信息。

实验在 MultiWOZ 2.2 的 test split 上完成，采用两层评测：**L1 选择质量**（不需要 LLM，秒级，可跑全量）与 **L2 任务完成率**（需要 LLM，只跑子集）。

主要结果：

1. **打分网络有效**。test AUC **0.9332**，显著超过最强的零成本基线（对话内相对位置，**0.8172**），差距 **+0.1160**。在固定预算 B=2048 下，跨长度关键信息召回率（CR）达 **0.7667**，纯向量检索为 0.4778，位置基线仅 0.2778。
2. **记忆过滤的价值在 L2 上被直接量化**。全量上下文（7,277 token）的任务准确率只有 **0.3222**，而打分过滤后（1,489 token，压缩 4.9 倍）是 **0.3778**；作弊基线 ORACLE 只用 **216 token** 就到 **0.8444**。**那 46.6 个百分点的差距不是「方法不够好」，而是「区分对话归属」这件事的价值**——纯文本打分器看不到对话边界，这是它的固有盲区。
3. **标签在三个独立口径下方向一致**。自建的弱监督标签（belief state 差分）经覆盖率口径（同分母配对下删重要轮的信息丢失率是删不重要轮的 **10.56 倍**）、JGA 口径（删重要轮答对率从 **0.9174** 掉到 **0.2477**，差值 **−0.6755**，p<0.001）、模拟抽检 κ（**0.430 / 0.500 / 0.707**）三重验证。
4. **消融显示三个超参均无显著影响**。层数、学习率、L2 正则的 AUC 跨度仅 **0.0013**，与种子间标准差 **0.0007** 同量级。1 层（99,585 参数）已是最优——题目写「浅层全连接」不是妥协，是正解。
5. **一个必须如实报告的负结果**：L2 上 B2 相对纯检索 B1 的优势只有 **+0.0222，p=0.6964，不显著**。180 条样本的功效不足以判定这个量级的差异。

## 2. 方法

### 2.1 整体结构

```
历史对话 ──切片──> 记忆片段（MemorySegment）
                      │
                      ├─ 句向量编码（all-MiniLM-L6-v2，384 维）
                      │        │
                      │        ├─> 向量检索库（余弦相似度）
                      │        └─> 重要性打分网络（384→256→256→1）
                      │                    │
                      └────────────────────┴─> 预算约束下的选择 select()
                                                    │
                                              拼装 prompt ──> LLM ──> 答案
```

四个模块，依赖单向（`memory → scorer → agent → eval`）：

| 模块 | 职责 |
|---|---|
| `memory/` | 轮次切片、句向量编码、长历史构造、向量检索、预算内选择 |
| `scorer/` | 重要性打分网络、数据集构造、训练、零成本基线打分函数 |
| `agent/` | prompt 构造、LLM 客户端（本地/API/Dummy）、响应缓存、单轮与多轮主循环 |
| `eval/` | 指标（CR / Recall@budget / NDCG / slot_acc / AR / token）、L1/L2 调度、报告 |

### 2.2 记忆片段与选择

**片段定义**：一轮对话 `(user, system)` 为一条记忆，token 数用 Qwen2.5 的 tokenizer 精确计数（不按空格估）。实测 test split 平均 **35.95 token**，中位 36，p90 59，max 152。

**选择函数 `select(scores, tokens, budget, reserve_recent=2)`** 单独成一个函数，这是公平性的代码级保证：**所有基线共用同一套截断逻辑，唯一变量是 scores 的来源**。

| 组 | scores 来源 |
|---|---|
| **B2（本题方法）** | 打分网络输出（全库稠密打分） |
| B1（仅向量检索） | query 与片段的余弦相似度 |
| B0（原始全量上下文） | 时间序，超预算后从头截断 |
| R0（位置基线）【自加】 | `-相对位置`（越早越重要） |
| R0A【自加】 | `-绝对轮次` |
| R1【自加】 | `+相对位置`（recency） |
| R2【自加】 | 随机 |
| R3【自加】 | 规则「前 3 轮」 |
| LEN【自加】 | 片段长度 |

**为什么 B2 走全库稠密打分而不是「先检索再重排」**：实测 needle 进入余弦 top-50 的比例在 L=128/256/512 分别是 **0.678 / 0.456 / 0.344**，且随历史变长而下降——「检索 top-50 再重排」在长历史上越用越差，与题目目标相反。而全库打分对 8,372 段只需 **0.014 秒**，成本可忽略。

### 2.3 打分网络

结构：`LayerNorm → Linear(384,256) → GELU → Dropout(0.1) → Linear(256,256) → GELU → Dropout(0.1) → Linear(256,1)`，共 **165,377 参数**（2 个隐藏层）。

训练配置：lr 3e-4、weight_decay 1e-4、batch 256、最多 20 epoch、早停 patience 3（监控 val AUC）、`pos_weight=auto`=**0.7993**。

**`pos_weight` 为什么必须用 auto**：本任务正例率是 **55.6%**（不是常见的 25–40%），若按惯例设 `负/正` 会变成 0.80 去**放大**正例，而实际方向相反（应下调）。这是实测发现的一个坑。

### 2.4 弱监督标签

MultiWOZ 2.2 提供逐轮的 belief state（累积对话状态）。定义第 t 轮重要，当且仅当：

1. 该轮引入了状态变化（`delta` 非空），**且**
2. 至少一个 `(slot, value)` 在对话结束时**仍是原值**

```
cur    = norm_state(states_22[t])              # {slot: [v]} → {slot: v}
delta  = {k: v for k, v in cur.items() if prev.get(k) != v}
n_valid = sum(1 for k, v in delta.items() if final.get(k) == v)
label  = int(n_valid > 0)
```

其中 `final` 取对话中**最后一个非空 state**（末尾可能有未标注轮，不能直接取最后一轮）。

标签统计：train 65,213 轮，正例率 **53.8%**；dev 56.8%；test 56.6%。

**已知偏差（必须交代）**：标签标的是「**引入**」而非「**必要**」。集合覆盖分析显示 test 上 **49.24%** 的轮次可删（正例中 **33.34%** 不在最小覆盖集），说明大量被标为重要的轮次其实是冗余的。这个限定在 §5 的校验里被量化。

### 2.5 数据对齐的一处修正

MultiWOZ 原始数据在一轮内**先存 system 再存 user**，即 `sys_utt[t]` 回复的是 `usr_utt[t-1]`。三条独立探针确认（test split）：

| 探针 | 结果 |
|---|---|
| 用户问 postcode（309 次） | 邮编落在 `sys[t+1]` **266 次（86.1%）**、`sys[t]` 7 次（2.3%） |
| 用户提 booking（844 次） | 确认落在 `sys[t+1]` **381 次**、`sys[t]` 35 次 |
| `sys` 以问号结尾（4,530 次） | 短答落在 `usr[t+1]` **1,015 次**、`usr[t]` 514 次 |
| **决定性** | **turn 0 的 `sys_utt` 在 1000/1000 段对话里都是 `none`**（首轮没有"上一轮的回复"） |

而状态标注对齐 user（delta 值出现在 `usr[t]` 占 71.8%、`usr[t-1]` 仅 2.5%）。故正确轮次定义是 `turn t = (usr_utt[t], sys_utt[t+1], states_22[t])`，已修正并全量重跑。

### 2.6 长历史构造

题目要求「长序列」，而 MultiWOZ 单段对话平均只有 **7.7 轮**（约 280 token），无法直接制造上下文溢出。构造方式：

1. 取一段真实对话为主对话（primary），保留其全部轮次
2. 从**同领域的其他对话**抽取干扰轮（decoy）补足到目标长度 L
3. 主对话轮次**等距铺开**（不是全挤在开头，否则位置基线会凭空获胜）
4. 干扰轮的 `turn_idx` 分布**匹配主对话**（只从 `turn_idx ∈ hist_idx` 的池里抽），否则绝对轮次基线会假性领先
5. needle 位置在 **0–90% 分位**随机

目标长度 L ∈ {128, 256, 512}。实际达到的规模：L=512 的 90 个场景里只有 23 个真到 512 轮（其余落在 354–486，因为候选池不够），这点在报告里必须注明，否则「512 轮也扛得住」会被误读。

### 2.7 两层评测

**L1（选择质量，不需要 LLM）**：

| 指标 | 含义 |
|---|---|
| **CR**（关键信息召回率） | needle 是否被选入上下文——零成本的关键杠杆 |
| Recall@budget | 主对话相关轮被选中的比例 |
| NDCG@k | 按打分排序的质量 |

L1 在 test 上 90 个场景跑完只需 **153.6 秒**，可跑全量。**这是本次实验设计上最重要的决定**：LLM 是唯一昂贵环节，其余全部免费。先跑 L1 全量，如果打分网络赢不过位置基线（AUC 0.8172）就停下，不浪费 20 分钟跑 L2——把「发现方法不行」的成本从小时级压到秒级。

**L2（任务完成率，需要 LLM）**：

| 指标 | 含义 |
|---|---|
| slot_acc | 逐槽位答对率（**主指标**） |
| scenario_success | 场景内全部槽位答对 |
| AR | 在可答子集上的准确率 |
| token 消耗 | 进上下文的 token 数 |

**任务形式**：定向填空。给定选出的上下文，问「The restaurant table is booked for ___ people.」这类模板，要求只回填缺失词。

**为什么用填空而不是问答**【自加，实测得出】：
- 问答式（"Answer with the exact value"）在 25 个数字槽位样本上只有 **5/25 = 0.20**
- 填空式 **13/25 = 0.52**
- 原因：问答式的问句自带数字（"for how many people"），弱模型会回显问句本身

30 个填空模板**一律不含数字**，且排除 `yes`/`no`/`dontcare` 这类无法字面匹配的符号值。

## 3. 实验设置

| 项 | 设置 |
|---|---|
| 数据 | MultiWOZ 2.2，test split 1,000 段对话 / 8,372 轮 |
| 训练/验证划分 | 按 `dialogue_id` 划分（防泄漏）；train 8,437 段 / dev 1,000 段 |
| 句向量模型 | `all-MiniLM-L6-v2`（384 维，英文） |
| 打分网络 | 384→256→256→1，165,377 参数 |
| 评测 backbone | DeepSeek-V4.1-Flash（API，`reasoning_effort=none`） |
| 上下文预算 | B=2048 token |
| L1 规模 | 90 场景（L=128/256/512 各 30）× 10 个选择器 |
| L2 规模 | 同 90 场景 × 每场景 2 个槽位 = 180 条 × 10 个选择器 |
| 统计方法 | 配对 bootstrap（5,000 次重采样），按场景×槽位配对 |

**硬件**：2 核 CPU、4 GB 内存、无 GPU。

**为什么用 API 而不是本地模型**：本地只能跑 Qwen2.5-0.5B（fp32 峰值 3.24 GB，已是内存上限下的极限）。实测 0.5B 的对话状态追踪能力不足——定向抽取 12 个槽位只中 4 个，`full` 条件下的绝对 JGA 只有 **0.589**，且 `train-day` 这类槽位只有 **0.036**（28 条对 1 条）。**0.5B 只能做配对比较，不能出绝对数**。故正式实验走 API。

## 4. 结果

### 4.1 L1：选择质量

**表 4-1 跨长度选择质量（test，90 场景，B=2048）**

| 选择器 | L=128 | L=256 | L=512 | 跨长度 CR | Recall@budget | NDCG@k |
|---|---|---|---|---|---|---|
| **B2（本题方法）** | **1.0000** | **0.7667** | **0.5333** | **0.7667** | **0.6051** | **0.2114** |
| LEN（长度基线） | 0.8333 | 0.5333 | 0.3000 | 0.5555 | 0.3620 | 0.1271 |
| B2R（两阶段，已弃用） | 0.6333 | 0.5000 | 0.3667 | 0.5000 | 0.3857 | 0.1849 |
| B1（仅向量检索） | 0.7000 | 0.4000 | 0.3333 | 0.4778 | 0.3649 | 0.1541 |
| R0（位置基线） | 0.4333 | 0.2000 | 0.2000 | 0.2778 | 0.3158 | 0.0573 |
| R2（随机） | 0.5000 | 0.1667 | 0.0667 | 0.2445 | 0.2731 | 0.0546 |
| R3（前 3 轮） | 0.4667 | 0.1000 | 0.0333 | 0.2000 | 0.2177 | 0.1274 |
| R1（recency） | 0.4000 | 0.1000 | 0.0000 | 0.1667 | 0.1947 | 0.0409 |
| B0（时间序截断） | 0.4000 | 0.1000 | 0.0000 | 0.1667 | 0.1947 | 0.0409 |
| R0A（绝对轮次） | 0.4000 | 0.0667 | 0.0000 | 0.1556 | 0.3400 | 0.1574 |

**B2 在三个长度上全部最优**，跨长度 CR 比最强的零成本基线（LEN，0.5555）高 21.1 个百分点，比纯检索（B1，0.4778）高 28.9 个百分点，比位置基线（R0，0.2778）高 48.9 个百分点。

**三条必须说清的观察**：

1. **「优势随历史变长而扩大」不成立**。B2/B1 比值 1.43× → 1.92× → 1.60×，B2−B1 绝对差 0.300 → 0.367 → 0.200，均非单调。领先幅度在 L≥256 后不再增长，**L=512 的 CR 0.5333 是当前最明显的短板**。
2. **B0 与 R1 完全相同**（0.4000 / 0.1000 / 0.0000）。这不是 bug，是必然：没有记忆模块时，「全量上下文」在超预算后就是按时间序从头截断，恰好等价于「越早越重要」。**B0 相对 R1 没有任何信息优势，只是更贵**。
3. **LEN 基线意外地强**（0.5555，仅次于 B2）。必须自查它是否只是复现了长度信号：`corr(score, n_tokens) = +0.6331`，确实相关；但按长度四分位分层后 AUC 仍为 **0.9464 / 0.9084 / 0.8675 / 0.8556**，说明内容信号独立有效。

### 4.2 L1：预算扫描（压缩率的影响）

默认 B=2048 在 L=128 时相当于保留 45.5% 的历史——「压缩」没真正发生。补测 B ∈ {256, 512, 1024, 2048}：

**表 4-2 预算扫描（每格 B2 / B1 / R0 的 CR，括号为保留比例）**

| 预算 B | L=128（库 4,497 tok） | L=256（库 8,910 tok） | L=512（库 16,874 tok） |
|---|---|---|---|
| 256 | 0.350 / 0.150 / 0.050（5.7%） | **0.100 / 0.125** / 0.000（2.9%） | **0.050 / 0.075** / 0.025（1.5%） |
| 512 | 0.475 / 0.275 / 0.100（11.4%） | 0.350 / 0.225 / 0.050（5.8%） | 0.225 / 0.100 / 0.050（3.0%） |
| 1024 | 0.875 / 0.350 / 0.150（22.8%） | 0.625 / 0.275 / 0.125（11.5%） | 0.400 / 0.275 / 0.075（6.1%） |
| 2048 | 1.000 / 0.700 / 0.425（45.5%） | 0.900 / 0.325 / 0.200（23.0%） | 0.625 / 0.275 / 0.100（12.1%） |

**结论要分开说，不能一句「全赢」带过**：

- **B=1024 与 B=2048 的 6 个格子，B2 全部第一**，且压缩越激进优势越大（L=512、B=1024：0.400 vs 0.275 vs 0.075）
- **B=256 的 3 个格子里有 2 个 B2 输给 B1**（加粗处）。这是真实负结果——**预算只够放 8–9 个片段时，稠密打分器的排序精度不如余弦相似度**。可能原因：打分器学的是「片段整体重要性」（与 query 无关的绝对判断），而余弦相似度直接对齐 query，极低预算下后者更不容易选错
- **R0 在全部 12 个格子里都最差或接近最差**，位置启发式在压缩场景下完全失效
- **L=512、B≤512 时所有方法都接近 0**（保留 1.5%–3.0%），此时任何选择器都救不回来，是「关键信息在极低预算下无法保障」的负结果

**推荐配置**：L=512 时 B=2048（保留 12.1%），B2 的 CR=0.625，相对 B1 的 0.275 是 2.3× 提升。

### 4.3 L1：消融实验

**表 4-3 三因素消融（test AUC，3 seeds）**

| 因素 | 取值 | test AUC | 标准差 | 参数量 | 相对位置基线 |
|---|---|---|---|---|---|
| **网络层数** | **1** | **0.9352** | 0.0007 | **99,585** | +0.1181 |

### 4.5 关键发现：ORACLE 216 token 84.4% vs B2 1,489 token 37.8%

这是本次实验最有信息量的数字对比，值得单独拆开。

**（1）不是「没选到」**

抽查 4 个 L=128 场景：

| 场景 | bank | 主对话段 | B2 选中 | 含主对话 | needle |
|---|---|---|---|---|---|
| MUL0003 | 128 | 6 段 / 296 tok | 48 段 / 2,010 tok | **5/6** | ✅ |
| MUL0004 | 128 | 5 段 / 231 tok | 46 段 / 2,022 tok | **5/5** | ✅ |
| MUL0011 | 128 | 11 段 / 411 tok | 45 段 / 2,041 tok | **8/11** | ✅ |
| MUL0014 | 128 | 6 段 / 302 tok | 49 段 / 2,047 tok | **6/6** | ✅ |

30 个 L=128 场景汇总：主对话段只被**漏选 36 段**，needle 全部选中。

**（2）是「选到的干扰轮把答案带偏」**

30 个 L=128 场景里有 **33 个（场景,槽位）组合**的选中上下文含「同槽位、不同值」的冲突干扰轮。例如：

- `hotel-area`：gold = `centre`，上下文里另一段对话说 `north`，模型答 `north`
- `hotel-stars`：gold = `0`，另一段对话说 `4`，模型答 `4`

**打分器无法知道某轮属于哪段对话**——这是纯文本打分的固有盲区。它能判断「这一轮在它自己的对话里重不重要」，但判断不了「这一轮对当前 query 是不是噪声」。

**（3）B0FULL 是最直接的证据**

B0FULL（题目字面义的「原始全量上下文」，7,277 token）的 slot_acc 只有 **0.3222**，比 B2 的 0.3778 还低，比 ORACLE 的 0.8444 低 **52 个百分点**。而且它的 token 数是 ORACLE 的 **34 倍**。

**上下文越长、干扰越多，强模型也会被带偏。** 这就是「记忆过滤」这件事存在的理由——不是为了省 token（虽然确实省了 4.9 倍），而是因为**不滤会答错**。

**（4）这个差距的诚实解读**

ORACLE 是作弊基线，所以正确的表述是：

> ORACLE 与 B2 的 **46.6 个百分点**差距，**不是「方法还不够好」，而是「任务本身有多难」的上界**。它说明：如果能把跨对话的干扰轮完美剔除，同样 216 token 就能到 84.4%。当前的打分网络做到了 37.8%——**中间那 46.6 个百分点，就是「区分对话归属」这件事的价值**。

这也直接指向改进方向：打分器目前只输入「单轮文本的句向量」，**看不到对话边界**。加一个 `dialogue_id` 特征（或做对话级聚类）可能比调网络层数有用得多。

**（5）token 消耗的实际含义**

| 选择器 | ctx token | 相对 B0FULL | slot_acc |
|---|---|---|---|
| ORACLE | 216 | **3.0%** | 0.8444 |
| NEEDLE | 39 | 0.5% | 0.3444 |
| B1 | 1,458 | 20.0% | 0.3556 |
| B0 | 1,482 | 20.4% | 0.3167 |
| **B2** | 1,489 | 20.5% | **0.3778** |
| B0FULL | 7,277 | 100% | 0.3222 |

B2 把上下文压到 B0FULL 的 **20.5%**，同时 slot_acc 从 0.3222 提到 0.3778。**压缩率 4.9 倍，指标还涨了 5.6 个百分点**——这是题目「在控制 token 开销的前提下保障关键信息不丢失」最直接的回答。

但要注意：**B2 的 token 数（1,489）与 B0/B1 几乎相同**（1,482 / 1,458），因为预算是硬约束 2,048，所有选择器都填满。**「省 token」这件事在固定预算下不体现为更少的 token，而体现为同样的 token 里装了更多有用的东西**——看 CR：B2 0.7667 vs B0 0.1667，是 **4.6 倍**。

## 5. 标签可信度校验【自加】

题目没有要求这一节，但**如果标签是错的，上面所有结论都不成立**。所以做了三个独立口径的校验。

### 5.1 口径一：反事实删除（覆盖率，字符串层面）

**思路**：删掉某组轮次后，query 时刻的 gold 状态里还有多少槽位值能在剩余上下文中找到文本支撑。

**口径细节**：
- gold 取 `hist[-1].state`（query 时刻的累积状态），**不是对话末尾的 state**（后者含未来信息）
- 值匹配用**整词正则** `(?<![a-z0-9])value(?![a-z0-9])`，否则 `'4'` 会命中 `'15:00'`、`'3'` 命中 `'3-4'`
- 排除符号值 `yes`/`no`/`dontcare`/`none`（原文里是 free wifi / no internet / any area，永不字面出现）
- 等量删除：`k = min(n_pos, n_neg)`，保证正负例删的轮数相同

**表 5-1 反事实删除结果（test）**

| 条件 | 信息丢失率 |
|---|---|
| 删 label=1（重要） | **26.84%** |
| 删 label=0（不重要） | **3.53%** |
| 删 label=0，**位置匹配** | 3.49% |
| 删随机 | 19.11% |

**位置混淆的排除（三层控制）**：

被删正例的平均位置是 **1.311**，被删负例是 **3.371**——正例天然靠前（首因），而靠前的轮次更可能是唯一支撑，差值可能混入位置效应。三层控制：

| 控制层 | 结果 |
|---|---|
| ① 位置匹配（给每个正例配位置最近的负例） | 丢失率仍 3.49%，配对差值 **+0.2616**（与未匹配的 +0.2610 几乎相同）→ **不是位置效应** |
| ② 位置分层（只在 turn 0–2 内比） | 20.74% vs 2.13% = **9.74 倍** |
| ③ 同分母配对（正负例在该区间都有可删轮的 454 段对话） | 22.17% vs 2.10% = **10.56 倍** |

三 split 一致：test **10.56×**、dev **13.23×**、train **10.71×**。

### 5.2 口径二：JGA（LLM 答题层面）

**思路**：给定上下文，让 LLM 回答 query 涉及的槽位值，看删掉某组轮次后答对率掉多少。

**为什么用「配对」而不是「绝对 JGA」**：绝对 JGA 需要完整对话状态追踪（DST），0.5B 做不到。但**配对口径**（比较「删正例 vs 删负例」的答对率差）只需要模型能做定向填空，弱模型也够用。实测决定性信号：有 needle 时答对 **13/25 = 0.52**，把上下文换成「(nothing relevant)」后 **1/25 = 0.04**，**13 倍差**。

**表 5-2 JGA 结果（API backbone，607 段对话 / 1,332 条槽位）**

| 口径 | 全量上下文 | 删重要 | 删不重要 | 删随机 |
|---|---|---|---|---|
| 槽位级准确率 | **0.9174** | **0.2477** | 0.9204 | 0.6839 |
| 可答子集准确率 | 1.0000 | **0.2676** | 0.9820 | 0.7332 |
| 对话级 JGA | **0.8270** | **0.1598** | 0.8353 | 0.5338 |

**表 5-3 配对比较**

| 对比 | 差值 | 95% CI | p |
|---|---|---|---|
| **删重要 − 删不重要** | **−0.6755** | **[−0.7117, −0.6359]** | **<0.001** |
| 删重要 − 删随机 | −0.3740 | [−0.4135, −0.3327] | <0.001 |
| 删不重要 − 删随机 | +0.3015 | [+0.2652, +0.3410] | <0.001 |

### 5.4 口径三：模拟抽检（Cohen's κ）

**声明：这不是人工校验。** 用户明确表示没有时间人工判断，所以用两个**决策过程不同**的规则判据做交叉验证：

- **J2 末次提及**：存在某个最终有效槽位值，本轮提到它、之后不再提到 → 1（比标签**宽**）
- **J3 唯一支撑**：某个最终有效槽位值在全对话中**只有本轮**提到 → 1（比标签**严**）

关系：`J3 ⊂ 标签 ⊂ J2`

**表 5-5 模拟 κ（n=200）**

| 对比 | κ | 一致率 | 95% CI | 解读 |
|---|---|---|---|---|
| 标签 vs J2 | **0.430** | 0.715 | [0.305, 0.550] | 中等一致 |
| 标签 vs J3 | **0.500** | 0.750 | [0.382, 0.608] | 中等一致 |
| J2 vs J3 | **0.707** | 0.855 | [0.612, 0.798] | 强一致 |

标签 vs J3 的混淆矩阵：tp 59 / tn 91 / fp 9 / fn 41，精确率 **0.8676**、召回 **0.59**。

**这个口径能证明什么、不能证明什么**：
- ✅ 能：标签与两个独立规则判据有中等以上一致，**不是随机噪声**
- ❌ 不能：证明标签与「人」一致。J2/J3 都基于 state 数据，与标签共享同一数据源，存在系统性偏差。**人工复核仍未做**

**一个被证伪的方案（负结果）**：最初想让 0.5B 直接读对话答 yes/no「这轮是否必要」，四种 prompt 写法全部退化：

| 写法 | 正例率 | κ |
|---|---|---|
| 直接问 | **0.033**（58/60 全答 no） | 0.067 |
| few-shot | 0.100 | −0.067 |
| 抽取式 | **1.000**（全答 yes） | 0.000 |
| A/B 选项 | 0.983 | 0.033 |

**0.5B 没有语义必要性判断能力，只被句法形式牵着走。** 这个负结果解释了为什么 JGA 必须用填空任务而非 yes/no。

### 5.5 标签的已知局限（必须写进报告）

1. **标签标的是「引入」而非「必要」**。集合覆盖显示 test 上 **49.24%** 的轮次可删（正例中 **33.34%** 不在最小覆盖集）。一次删光所有 necessity=0 的轮次仍丢失 **12.93%**——因为某值两轮都提到时两轮 necessity 都是 0，但同时删就丢。
2. **假设最终状态即全部目标**。电话/邮编类查询不进 belief state（实测 system 回复里有电话的对话占 48.6%，但 state 里电话槽位 0/1000）。
3. **位置偏置**：正例率 turn 0 为 85.0% → turn 10 降到 16.0%（**primacy，首因**）。已用 R0 基线（AUC 0.8172）和分层 AUC 双重控制。
4. **是弱监督，不是 ground truth**。

### 5.6 换标签的对照实验（负结果）

**83.3% 的场景结果完全相同。结论：不改标签。** 力气应转向长历史（L=512 的 CR 只有 0.5333）与 L2。

## 6. 讨论

### 6.1 三个指标之间的关系

题目要求报「任务完成率、token 消耗、关键信息召回率」，这三者不是并列的，而是**层层衰减**：

```
CR 0.7667  ──(干扰轮污染)──>  slot_acc 0.3778  ──(多轮交互)──>  ?
   选择层面                        单轮答题                     多轮任务
```

- **CR 到 slot_acc 的衰减**是本次最大的发现：CR 高 28.9 个百分点（vs B1），slot_acc 只高 2.2 个百分点且不显著
- 衰减的主因是**跨对话的冲突干扰**（33 个组合），不是选择失败
- 这解释了为什么 ORACLE（无干扰）能到 0.8444

### 6.2 「浅层」这件事

题目说「浅层全连接神经网络」，消融显示：

- 1 层 99,585 参数：AUC **0.9352**
- 4 层 296,961 参数：AUC 0.9339

**参数增加 3 倍，指标反而略降。** 这不是「题目限制了我们」，而是「这个任务本身不需要深网络」——输入是 384 维句向量，已经过预训练模型压缩，判据主要是「这轮有没有引入状态变化」，是低阶特征。

### 6.3 什么情况下这个方法不适用

1. **极低预算**（B=256，只够 8–9 个片段）：打分器不如余弦相似度
2. **长历史**（L=512）：CR 掉到 0.5333，且 B1 在 L2 上反超
3. **对话归属未知**：这是当前最大的盲区（§4.5）
4. **可复述信息为主的场景**：标签会高估必要性（§5.3）

### 6.4 与题目的对照

| 题目要求 | 完成情况 |
|---|---|
| 搭建具备记忆模块的对话智能体 | ✅ 四模块齐全（`memory`/`scorer`/`agent`/`eval`），含向量检索库、prompt 构造、响应缓存、单轮与多轮主循环 |
| 构造记忆样本数据集，训练全连接打分网络 | ✅ 65,213 轮弱监督样本，384→256→256→1，test AUC 0.9332 |
| 三组基线对比（全量 / 仅检索 / 检索+打分） | ✅ B0 / B1 / B2 三组齐全，另加 6 组零成本基线【自加】 |
| 消融：层数 / 学习率 / L2 正则 → 三指标 | ✅ 12 个配置 × 3 seeds，结论是三者均无显著影响 |
| 选做 1：注入错误记忆观察失效场景 | ⚠️ **部分完成**——§4.5 的冲突干扰分析本质就是「错误记忆」，但未做系统的注入实验 |
| 选做 2：打分基础上加摘要压缩 | ❌ 未做 |

## 7. 局限与改进

### 7.1 本次实验的局限

1. **L2 样本量不足**：180 条，B2−B1 的 p=0.6964 无法区分「无差异」与「样本不够」。要判定需要 500+ 场景。
2. **只有一个 backbone**：「删噪声有益」在 0.5B 上显著、在 API 上不显著，说明这类结论对模型能力敏感，不能外推。
3. **干扰轮是合成的**：真实多会话 Agent 的干扰分布未必与「同领域其他对话的轮次」相同。
4. **没有多轮主循环**：每个场景只问一次，没有「答完再看下一步」的交互。题目说的「Agent」在这一点上只是单轮问答 + 记忆模块。
5. **人工抽检未做**：κ 是模拟值（0.430 / 0.500），不是人工 κ。
6. **L=512 只有 23/90 场景真到 512 轮**：候选池不够，其余落在 354–486。

### 7.2 最值得做的三个改进

1. **给打分器加对话归属特征**。这是 ORACLE 与 B2 差 46.6 个百分点的根因。当前输入只有单轮句向量，可以加：
   - `dialogue_id` 的 embedding
   - 对话级聚类后的一致性特征
   - 相邻轮次的上下文窗口（而非单轮）
2. **扩到 500+ 场景**，让 B2−B1 的差异可判定。
3. **真做多轮主循环**：`agent/loop.py` 已有 `run_scenario`，但 L2 只调了单轮 `run_turn`。

## 9. 结论

1. **方法成立**。打分网络 test AUC **0.9332**，显著超过最强的零成本基线（0.8172），差距 +0.1160。在固定预算下跨长度 CR **0.7667**（纯检索 0.4778，位置基线 0.2778）。
2. **记忆过滤的价值被量化**。全量上下文 7,277 token 只有 0.3222，打分过滤后 1,489 token 有 0.3778，ORACLE 216 token 有 0.8444。**中间 46.6 个百分点是「区分对话归属」的价值**。
3. **「浅层」是正解**。1 层 99,585 参数的 AUC（0.9352）高于 4 层 296,961 参数（0.9339）。
4. **超参不敏感**。层数、学习率、L2 正则的 AUC 跨度（0.0013）与种子标准差（0.0007）同量级。但 L2 正则的「无影响」是平凡成立的（早停在 ep5 先触发）。
5. **标签方向正确但标的是「引入」而非「必要」**。三口径一致（覆盖率 10.56×、JGA −0.6755、模拟 κ 0.43–0.50），但 49.24% 的轮次可删，且标签在可复述信息上会高估必要性。
6. **必须如实报告的负结果**：B2 相对 B1 在 L2 上不显著（+0.0222，p=0.6964）；B=256 时打分器不如余弦（2/3 个格子）；「删噪声有益」在强模型上消失。
