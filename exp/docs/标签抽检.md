# 标签抽检（模拟 Cohen's κ）

> **这一页不是人工校验。**
> 用户没有时间逐条判断 60 条样本，所以用两个**独立于标签规则**的自动化判据模拟。
> 它证明的是「**标签与两种独立自动化判据一致**」，不是「**标签与人一致**」。
> 报告里引用时必须写明这是模拟值，真人复核仍是未完成的待办。

---

## 0. 为什么不能只做一次

标签的定义是：

> 第 `t` 轮为 important ⟺ 本轮 belief state 相对上一轮有新增/更新，**且**该 slot-value 在对话结束时仍然有效。

如果拿同一套 state/delta 数据再判一次，那是同义反复，κ 必然接近 1，毫无信息量。所以必须换**决策过程不同**的判据。

## 1. 先试了 LLM 判据，失败了

最初的设计 J1 是让 0.5B 直接读「本轮 user+system 原文」和「对话最后的 query」，回答 yes/no。实测**四种写法全部退化**（`exp/runs/20261124_032705_judge_probe/`，n=60，总耗时 241 秒）：

| 写法 | prompt 要点 | 正例率 | κ(标签) |
|---|---|---|---|
| 直接问 | "Is the information in the TURN needed?" | **0.033**（58/60 全答 no） | 0.067 |
| few-shot | 一正一负两个例子 | **0.100** | −0.067 |
| 抽取式 | "填不出就回 NONE" | **1.000**（全部填了） | 0.000 |
| A/B 选项 | "A) yes B) no，只回字母" | **0.983** | 0.033 |

正例率要么趋近 0 要么趋近 1，模型没有判断力，只是被句法形式牵着走。

**这个负结果本身有用**：它解释了为什么 §4.4.1 的 JGA 校验必须用「填空能不能答对」这种**任务型**探针，而不能用 yes/no。0.5B 的语义必要性判断不可用，但它做定向抽取是有效的（with-needle 0.52 vs no-needle 0.04）。

## 2. 实际使用的两个判据

两个都基于 state 数据，但**规则与标签不同**，且都实测有区分度。

### J2 — 末次提及（`judge_last_mention`）

> 存在某个最终有效的槽位值，本轮提到了它，**之后不再提到** → 判 1。

与标签的差别：标签问「这一轮**引入**了什么」（delta 非空）；J2 问「这一轮是否**此后不可替代**」。J2 **允许之前出现过**，所以口径更宽。典型分歧：某个值在 t1 和 t3 都提到，t3 之后再没有——标签看 t1 是引入（1）、t3 是重复（0）；J2 看 t1 不是末次（0）、t3 是末次（1）。

### J3 — 唯一支撑（`judge_unique_support`）

> 存在某个最终有效的槽位值，**全对话只有本轮提到它** → 判 1。

这就是 `verify_counterfactual.py` 里的 necessity。比 J2 严格（J2 允许多轮提到，只要本轮是最后一次）。

### 两者夹住标签

```
J3（唯一支撑，最严）  ⊂  标签（引入 + 结束仍有效）  ⊂  J2（末次提及，最宽）
```

严格说这个包含关系不是数学必然（标签要求 delta 非空，J2 不要求），但方向上 J3 最保守、J2 最宽松。实测正例率：标签 0.500（抽样时正负例各半）、J2 0.485、J3 0.340，符合预期。

**κ(J2, J3) 用来模拟「两个标注者之间的一致性」**——它是这里唯一一个「两个判据互相比」的量，最接近人工 κ 的含义。

## 3. 结果

`exp/runs/20261124_033153_spot_check2_n200/spot_check2.json`，test split，n = 200（正负例各半）。

| 对比 | Cohen's κ | 一致率 | 95% CI（2000 次 bootstrap） |
|---|---|---|---|
| 标签 vs J2（末次提及） | **0.430** | 71.5% | [0.305, 0.550] |
| 标签 vs J3（唯一支撑） | **0.500** | 75.0% | [0.382, 0.608] |
| **J2 vs J3（两判据互相）** | **0.707** | 85.5% | [0.612, 0.798] |

混淆矩阵（标签 vs J3，n=200）：

|  | J3=1 | J3=0 |
|---|---|---|
| **label=1** | 59 | 41 |
| **label=0** | 9 | 91 |

精确率 **0.868**、召回率 **0.590**。**假阳性（标签说重要、唯一支撑说不是）有 41 条，假阴性 9 条**——标签比「唯一支撑」更宽松，与它的定义（引入即算，不要求唯一）一致：它会把「引入了新值但该值别处也提到」的轮次算作重要，所以主要误差在 fp 一侧。

n=60 时的结果（`exp/runs/20261124_033143_spot_check2/`）：κ 分别为 0.433 / 0.567 / 0.674，一致率 0.717 / 0.783 / 0.833，CI 更宽。**n=200 是主报口径**。

## 4. 怎么解读这些数

按 Landis & Koch 的常用分档：κ < 0.20 差、0.21–0.40 一般、0.41–0.60 中等、0.61–0.80 强、> 0.80 几乎完全一致。

- **标签 vs 两个独立判据：0.43–0.50，属「中等一致」**。说明标签不是随机的，但也确实有可观的边界模糊——大约 1/4 到 1/3 的样本上，两个判据会给出不同结论。
- **两个判据互相：0.707，属「强一致」**。J2 与 J3 的规则完全不同（一个看「之后是否还提」，一个看「是否唯一」），却能在 85.5% 的样本上一致，说明「必要/非必要」这个判断本身是有稳定内核的。
- **标签落在两者之间**：与较宽的 J2 一致度 0.430，与较严的 J3 一致度 0.500，符合「标签口径居中」的预期。

## 5. 这不能证明什么

1. **不是人工校验**。真人可能用「信息是否被后续轮次依赖」这种更贴近任务的判据，与两个自动化判据都不同。
2. **J2 与 J3 共享 state 数据**，所以它们的一致不完全是「独立」的。真正独立的只有 §4.4 的覆盖率口径（纯字符串匹配）和 §4.4.1 的 JGA 口径（LLM 答题）。
3. **样本只有 200 条**，来自 test split 的 672 段可配对对话。CI 宽度约 ±0.11，不足以区分 0.43 与 0.50。
4. **判据本身可能继承标签的系统性偏差**。J2/J3 都用 `hist[-1].state` 作 gold，如果 state 标注本身在某类槽位上错，三者会一起错。

## 6. 抽检表

`exp/docs/标签抽检表.csv`，60 行，正负例各 30。列说明：

| 列 | 含义 |
|---|---|
| `dialogue_id` / `turn_idx` | 对话与轮次 |
| `label` | 标签值（1 = 重要） |
| `delta` | 本轮新增/更新的槽位 |
| `query` | 本轮用户提问 |
| `response` | 本轮系统回复（**已修正 system 错位**，见 `exp/data/README.md`） |
| `gold_state_at_query` | query 时刻的累积状态 |
| `必要性(唯一支撑数)` | necessity，本轮是多少个槽位的唯一支撑 |
| `你的判断(1=该轮信息对回答query必要, 0=不必要)` | **模拟值已填 50 条**，10 条分歧留空 |
| `备注` | 填的是「模拟：J2/J3 一致」或「模拟：判据分歧 J2=x J3=y（留空待人工）」 |

**10 条分歧条**（J2=1、J3=0）是人工复核时最该看的：这类轮次「之后再没人提到」但「不是唯一支撑」，正好是标签边界最模糊的地方。
