# 什么是「belief state 差分标签」

> 一句话：MultiWOZ 每一轮都带一份**累积**的对话状态（belief state），把相邻两轮相减，就能自动判断「这一轮有没有带来新的关键信息」，不需要人工标注。

这是本项目的**全题地基**——题目要求「构造记忆样本数据集，训练打分网络输出记忆片段重要性得分」，但「记忆有多重要」没有现成标签。本组用 MultiWOZ 自带的标注做弱监督，把「重要性」操作化成「这一轮有没有引入仍然有效的新信息」。

---

## 1. 原始数据长什么样

MultiWOZ 2.2 给每一轮都标了一个 `dialogue_state`，形如 `{slot: value}`：

```
对话 MUL0002，第 0–4 轮：

t0  user: "Looking for a place to eat in the city center."
    state: {restaurant-area: centre}

t1  user: "I'd like to have some Chinese food."
    state: {restaurant-area: centre, restaurant-food: chinese}

t2  user: "I am looking for a moderately priced place to eat,
           I am also looking to book a ..."
    state: {hotel-name: bridge guest house,
            restaurant-area: centre, restaurant-food: chinese,
            restaurant-pricerange: moderate}

t3  user: "Before I commit I have a few questions. What area is the hotel located in?"
    state: {hotel-name: bridge guest house, restaurant-area: centre,
            restaurant-food: chinese, restaurant-pricerange: moderate}   ← 没变

t4  user: "Does it provide free parking?"
    state: {hotel-name: bridge guest house, hotel-parking: yes,
            restaurant-area: centre, restaurant-food: chinese,
            restaurant-pricerange: moderate}                            ← 新增 hotel-parking
```

关键：**`state` 是累积的**，不是每轮独立。t2 的状态包含 t1 的 `restaurant-food`，只是多了两项。

## 2. 差分：把「新增/更新」提出来

`delta(t) = { k: v ∈ state(t) | state(t-1)[k] ≠ v }`

即：本轮状态里，**值跟上一轮不一样的槽位**。上例：

| 轮 | `delta` | 含义 |
|---|---|---|
| t0 | `{restaurant-area: centre}` | 首轮，从零建立 |
| t1 | `{restaurant-food: chinese}` | 新增菜系 |
| t2 | `{hotel-name: bridge guest house, restaurant-pricerange: moderate}` | 同时新增两项 |
| t3 | `{}` | 只是提问，没带来新信息 |
| t4 | `{hotel-parking: yes}` | 新增停车信息 |

这一步把「用户说了一句话」变成「用户这句话是否改变了任务状态」。

## 3. 第二个条件：仍然有效

只看 `delta` 不够。用户可能先说「要 3 晚」，后面改成「2 晚」——前一轮的 `hotel-stay=3` 是**废弃值**，标成重要就是在灌噪声。

所以加第二个条件：

> 第 t 轮为 **important** ⟺ `delta(t)` 非空，**且**其中至少一个 `(slot, value)` 在**对话结束时**仍然存在。

`label = int(n_valid > 0)`，`n_valid` = `delta` 中在最终状态里仍保持原值的槽位个数。

这就是本组比 v1 README 多出来的一条。v1 只写了「某轮首次引入或更新了某个 slot 值 → 标为重要」，会把中间废弃的值也算进去。

## 4. 落到数据上

每条 JSONL 记录（`data/processed/multiwoz22/train.jsonl`）：

```json
{
  "dialogue_id": "MUL0002.json",
  "turn_idx": 2,
  "user": "I am looking for a moderately priced place to eat, ...",
  "system": "That narrows down the restaurant choices to 10. ...",
  "state": {"hotel-name": "bridge guest house", "restaurant-area": "centre",
            "restaurant-food": "chinese", "restaurant-pricerange": "moderate"},
  "delta": {"hotel-name": "bridge guest house", "restaurant-pricerange": "moderate"},
  "n_valid": 2,
  "label": 1,
  "dialogue_has_state": true
}
```

`state` / `delta` 留给报告和错误分析用；训练时只用 `label` 和轮次文本（先编码成向量）。

### 校验结果（train）

```
C1 label 与 n_valid 一致        65213 轮，异常 0
C2 delta 等于状态差集            62226 轮，异常 0
C3 槽位值回退统计                A→B→A 共 155 次（数据噪声，非错误）
C4 空状态不夹在中间              开头 821 / 全空对话 2166 / 中间 0
C5 slot 级覆盖统计               有效 91.2% / 改值 7.7% / 消失 1.12%
```

C4 值得解释：2,987 轮没有状态标注。查过位置分布，**没有一轮夹在对话中间**——821 轮在开头（等价于从零开始，无害），2,166 轮属于整段对话都没标注（`dialogue_has_state=false`，训练时应剔除）。所以不会出现「中间一轮把累积状态清空、下一轮被误判为全部新增」的问题。

C3 的 155 次回退是真实数据噪声，例如 `MUL0023: hotel-day = saturday → sunday → saturday`（用户确实改主意又改回来），不是 bug。

### ⚠️ 已知问题：标签和位置强相关（已处理）

这是数据分布问题，与标签逻辑本身无关：

| 轮次 | 0 | 1 | 2 | 3 | 5 | 7 | 10 |
|---|---|---|---|---|---|---|---|
| 正例率 | 85% | 77% | 67% | 61% | 50% | 29% | 16% |

后果：一个只会说「越靠前越重要」的规则就能拿到 **AUC 0.8065（val）/ 0.8172（test）**。打分网络如果只学会这个，AUC 很好看，但完全没读内容。

**已实施的处理**（见 [`../docs/L1实验结果.md`](../docs/L1实验结果.md)）：

- 加位置基线 **R0**（`-rel_pos`），实测 CR 只有 0.2556，而打分网 B2 是 0.7815——网络确实读了内容。
- needle 位置随机化到 0–90% 分位。
- 打分网 test AUC **0.9332** vs 位置基线 0.8172，margin +0.1160；分层 AUC 在位置最靠后的四分位仍达 0.9220。

### ✅ 反事实删除校验：已做，结论是「标签方向对，但偏保守」

完整结果见 [`../docs/反事实删除校验.md`](../docs/反事实删除校验.md)。因为 0.5B backbone 跑不动绝对 JGA，改用**零 LLM 成本的覆盖率口径**：删掉某组轮次后，query 时刻的 gold 槽位值还有没有文本支撑。

| 删除条件（等量删 k 轮） | 丢失率 |
|---|---|
| 删 label=1（重要） | **26.8%** |
| 删 label=0（不重要） | **3.5%** |
| 删随机（对照） | 19.1% |

正例天然集中在开头（平均位置 1.311 vs 负例 3.371），而靠前的轮次更可能是唯一支撑——这是必须排除的混淆。做位置匹配后差值几乎不变（+0.2610 → +0.2616）；只在 turn 0–2 内比较是 **9.74 倍**，同分母配对（454 段对话）是 **10.56 倍**。三个 split 一致（test 10.56× / dev 13.23× / train 10.71×）。

**但有一个重要限定**：逐轮看，label=1 轮中有 **42.0%** 不是任何槽位值的唯一支撑。但逐轮判据不能直接当可删比例（两轮都提到同一个值时，单独删任一轮都不丢，同时删就丢）——实测删光所有 necessity=0 的轮次仍丢失 **12.93%**。用**集合覆盖**算：**49.2% 的轮次可删**，正例中 **33.3%** 不在最小覆盖集里。也就是说，标签标的是「**引入**」新信息，不是「**必要**」信息。对「过滤冗余记忆」这个任务，标签偏保守。

**标签逻辑本身未被 system 修正影响**：`delta` 只来自 `states_22`，`final` 也只来自 state，不读文本。所以 C1–C5 五项校验结果与修正前完全相同（65,213 轮、异常 0、位置基线 0.8030）。变的是覆盖率口径——它要匹配文本，而文本变了。

## 6. 怎么复现

```bash
cd ~/高级机器学习
source exp/env.sh
python exp/scripts/download_data.py      # 下 parquet
python exp/scripts/prepare_multiwoz.py   # 生成 JSONL + 标签
python exp/scripts/verify_labels.py      # 标签逻辑校验（5 项）
python exp/scripts/verify_counterfactual.py --split test   # 反事实校验（1.4 秒）
```

`prepare_multiwoz.py` 里的核心逻辑只有三行：

```python
cur   = norm_state(r.states_22)                          # {slot: [v]} → {slot: v}
delta = {k: v for k, v in cur.items() if prev.get(k) != v}   # 差分
n_valid = sum(1 for k, v in delta.items() if final.get(k) == v)  # 仍有效
label = int(n_valid > 0)
```

`final` 是对话中最后一个非空 `state`（末尾可能有未标注轮，不能直接取最后一轮）。

## 7. 这个标签的局限（报告里要写）

1. **它是「状态变化」，不是「对话有用性」。** 一轮没改变状态，也可能是必要的确认（"是的，就是那家"），但会被标成不重要。
2. **它假设「最终状态」就是全部目标。** 用户问过的信息（电话、邮编）不进状态，但这些轮对任务完成同样关键。
3. **位置偏置**（见 §5）。这不是标签错了，是「重要性」在不同位置确实分布不均，需要实验设计去抵消。
4. **弱监督，不是 ground truth。** 反事实校验已验证方向正确（删正例丢失率是删负例的 10.56 倍），但标签标的是「引入」而非「必要」：集合覆盖显示 49.2% 的轮次可删（正例中 33.3%）。模拟 κ 显示与两个独立判据中等一致（0.43–0.50），真人复核仍待做。
