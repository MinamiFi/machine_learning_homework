## 3. 代码怎么跑

### 3.1 环境

```bash
cd code
bash scripts/setup.sh          # 装依赖（约 10 分钟）+ 下载模型（约 1 GB）
source env.sh                  # 设置 PYTHONPATH / HF 镜像 / 线程数
```

- Python 3.11，CPU 即可（本次实验环境：2 核 / 4 GB / 无 GPU）
- 依赖版本快照见 `requirements.lock.txt`
- 两个模型：`all-MiniLM-L6-v2`（句向量，88 MB）、`Qwen2.5-0.5B-Instruct`（本地 backbone，953 MB）
- **注意**：脚本里 `from src.xxx import ...`，必须在 `code/` 目录下执行，或把 `code/` 加进 `PYTHONPATH`

### 3.2 一键复现（不含需要 API 的 L2）

```bash
bash scripts/run_all.sh --skip-l2     # 约 25 分钟
```

### 3.3 分步（推荐，便于定位）

```bash
python3 scripts/download_data.py           # 数据（约 2 分钟）
python3 scripts/prepare_multiwoz.py        # 处理 + 打标签
python3 scripts/verify_labels.py           # 标签一致性校验（5 秒）
python3 scripts/build_memory.py --split train dev test   # 句向量（约 7 分钟）
python3 scripts/train_scorer.py            # 训练打分网络（约 16 秒）
python3 scripts/eval_l1.py --tag eval_l1_full2           # L1（约 2.5 分钟）
python3 scripts/run_ablation.py            # 消融（约 7 分钟）
python3 scripts/budget_sweep.py            # 预算扫描
python3 scripts/verify_counterfactual.py --split test    # 标签校验一
python3 scripts/simulate_spot_check2.py --n 200          # 标签校验三
python3 scripts/make_figures.py            # 出图
python3 scripts/verify_docs.py             # 文档数字自检（181 项）
```

### 3.4 需要 LLM 的部分

**L2 任务完成率与 JGA 需要一个 LLM backbone。** 两种方式：

**(a) API（本次实验用的方式，推荐）**

```bash
export DSH_EXP_API_KEY=你的key        # 只从环境变量读，不要写进配置文件
# 然后把 configs/agent.yaml 的 backbone 改成 api
python3 scripts/jga_check.py --n-dialogues 607 --max-slots 3 --tag jga_api_full
python3 scripts/eval_l2.py --n-per-length 30 --max-slots 2 --tag l2_main_api2
```

`configs/agent.yaml` 里需要同时设置 `api.base_url` 与 `api.model`。**若模型是推理模型（返回体含 `reasoning` 字段），必须设 `api.reasoning_effort: "none"`**，否则 token 预算会被思考过程吃光、`content` 返回 null。

**(b) 本地模型**

```yaml
backbone: local
local:
  path: models/Qwen2.5-0.5B-Instruct
```

**但本地 0.5B 出不了绝对数**：实测它的绝对 JGA 只有 0.589（API 是 0.9174），`train-day` 这类槽位只有 0.036。**只能做配对比较，不能出主表。**

### 3.5 自检

```bash
python3 scripts/test_src.py     # 单元自检：48 项，1 秒，不加载模型
python3 scripts/verify_docs.py  # 文档数字自检：181 项，20 秒
```

`verify_docs.py` 会把文档里声称的每个数字**从 `results/runs/` 的 json 重新算一遍**再比对，不一致就报 FAIL 并返回非 0。它抓到过 3 个错误（相关性系数抄错、把 CR 抄成召回率、消融配置写错段导致假结论），所以保留在包内。

## 5. 复现时需要知道的三个坑

这三个坑都实际踩过，且都影响结论，写在这里避免重复：

1. **`hash()` 有随机盐**。Python 3 对 str/tuple 的 `hash()` 每次进程加盐，若用它生成场景随机种子，**同数据同 seed 每次跑出的场景完全不同**，缓存全失效。已改为 `common.stable_seed()`（sha256）。`test_src.py` 里有跨子进程的回归测试。
2. **MultiWOZ 原始数据一轮内先 system 后 user**。直接取 `(usr[t], sys[t])` 会得到「本轮提问 + 上一轮提问的回复」，语义错位。正确轮次是 `(usr[t], sys[t+1], states[t])`。`prepare_multiwoz.py` 已修正。
3. **推理模型会吃掉 token 预算**。`max_tokens=16/24` 时 reasoning 用满、`content` 返回 null。必须 `reasoning_effort="none"`。

**本包不含任何 API key。** 密钥只从环境变量 `DSH_EXP_API_KEY` 读取，配置文件中只出现变量名。
